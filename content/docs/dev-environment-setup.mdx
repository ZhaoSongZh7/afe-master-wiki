Get a brand-new machine ready to work. Follow these in order; individual tools
have their own pages.

## Before you start

- Make sure you've completed [Before Day One](/docs/before-day-one) (badge + laptop).
- Have your accounts and credentials ready — see [Who's Who](/docs/whos-who) if
  you're missing access.

## 1. Accounts & access

Set up these accounts in order (some depend on others):

1. **Amazon A to Z** ([atoz.amazon.work](https://atoz.amazon.work/)) — your employee portal for payroll, benefits, and trainings
2. **Midway authentication** — Amazon's internal auth system; most internal sites require it
3. **Cloud Desktop (CDD)** — your remote development machine. Request through your manager or IT if not pre-provisioned.
4. **Code Browser / code.amazon.com** — access to internal code repositories
5. **Isengard** — AWS account access (your manager will add you to relevant accounts)

<Callout type="warn" title="If accounts aren't ready">
  If any access isn't provisioned by Day 1, tell your manager or onboarding buddy immediately. They can expedite through IT.
</Callout>

## 2. IDE & editor

We recommend using whatever IDE your team uses, as they can give you direct support. The two officially supported options:

| IDE | Best for | Setup guide |
| --- | --- | --- |
| **VS Code** | Flexible, configurable, Brazil/Viceroy integration | [VSCode Setup Instructions](https://w.amazon.com/bin/view/Users/kafaro/Quip/VSCodejavaAMZN/) |
| **IntelliJ IDEA** | Java/Kotlin, more stable Brazil integration | [IntelliJ Setup Instructions](https://w.amazon.com/bin/view/IntelliJ/) |

To connect your IDE to your Cloud Desktop via SSH, follow the setup guide for your chosen editor.

## 3. Command line & build tools

### Brazil Build System

Amazon uses **Brazil** for code management and builds. Key commands you'll use daily:

```bash
# Set up a workspace
brazil workspace create --name MyWorkspace
brazil workspace use -p PackageName

# Build a package (run from inside the package directory)
cd src/PackageName
brazil-build release

# Create a code review
cr --new
```

See the [SDE Intern Foundations](https://w.amazon.com/bin/view/EE/Learn/SDEOnboarding/InternOnboarding/) for a guided walkthrough of Brazil and CRUX.

## 4. Your onboarding training path

Follow this week-by-week path from [SDE Intern Foundations](https://w.amazon.com/bin/view/ASBX/Learn/SDEOnboarding/InternOnboarding/):

| Week | Goal | Key activities |
| --- | --- | --- |
| **Week 1** | Get set up, do your first code review | SDE Bootcamp, BT101 Workshop, team environment setup |
| **Week 2** | Take on your first coding task | BT102 (Local Development with Brazil), small task from team backlog |
| **Week 3** | Start sketching your project | Write design doc, explore tools/concepts needed for project |
